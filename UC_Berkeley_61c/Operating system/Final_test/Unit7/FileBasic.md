# 第4关：第七章基础 —— 文件基础与逻辑结构

**【核心目标】** 搞懂文件在“用户（你）的眼里”是什么样子的，以及为了方便查找，系统是怎么在文件内部组织数据的。

### 1. 文件基础（大纲要求：属性、操作、类型、保护）
这部分极其贴近日常使用，我们快速过一遍，凭生活经验就能拿分：

*   **文件属性：** 就是你平时在电脑上对着一个文件“右键 -> 属性”看到的东西。比如：文件名、类型（扩展名如.txt, .mp4）、大小、创建时间、修改时间、**保护级别（只读、隐藏等）**。
*   **文件操作：** 创建、删除、读、写、截断（把文件内容清空但保留文件本身）、设置读写位置（寻址）。
*   **文件保护：** 怎么防止别人偷看或乱改你的文件？
    *   最常考的方法是**“访问控制表 (ACL)”**。就像是一个贵宾名单，上面写着“张三可以读和写，李四只能读，王五不能看”。系统通过核对这个名单来保护文件。

---

### 2. 文件的逻辑结构 (大纲要求：顺序、索引、索引顺序) —— 【重点考点】

**【非常重要的前提】** 
一定要搞懂什么是“逻辑结构”！
**逻辑结构**，指的是**在用户/程序员眼里**，这个文件里面的内容是怎么排列的。它不管文件真正在硬盘上是连着存还是分开存的（那是物理结构，下一关讲）。
假设一个文件由100条“记录”（比如100个学生的成绩）组成，我们怎么组织这100条记录？

**① 顺序文件 (Sequential File)**
*   **原理：** 就像一盒**老式磁带**。100个学生的成绩，按照学号顺序，一个挨着一个紧紧排在一起。
*   **优点：** 如果你要从头到尾把所有成绩统计一遍（这叫**批量处理**），顺序文件是速度最快的。
*   **缺点：** 
    *   **查找太笨：** 如果你要找第99个学生，你只能从第1个开始往后数（如果是变长记录的话）。
    *   **增删困难：** 如果你想在第2和第3个学生之间插一个新学生，你得把后面98个学生全往后挪一个位置，非常麻烦。

**② 索引文件 (Index File)**
*   **原理：** 就像一本**厚厚的字典前面的目录**。文件本身的数据可能乱七八糟放着，但是系统为你建立了一张“索引表”。索引表里写着：“张三的数据在第10页，李四在第50页”。
*   **优点：** 
    *   **查找极快（支持随机访问）：** 想找李四？直接查索引表，瞬间跳到第50页。
    *   **方便修改：** 增加一个新学生，只要把数据随便找个空地放下，然后在索引表里加一条记录就行，不需要挪动其他人。
*   **缺点：** 索引表本身也是要占空间的。如果文件很小，索引表反而成了累赘。

**③ 索引顺序文件 (Index-Sequential File)**
*   **原理：** 这是上面两者的**完美结合**！就像**百家姓或者电话簿**。
    *   先把所有学生**分组**（比如按姓氏：赵组、钱组、孙组...）。
    *   组和组之间，或者为每个组建立一个**索引表**（查索引知道“钱组”在哪里）。
    *   但是在“钱组”的**内部**，钱一、钱二、钱三是按照**顺序**挨个存放的。
*   **优点：** 极大地缩小了索引表的体积（不需要为每一个学生建索引，只要为每一组建索引），同时又保持了比较快的查找速度。这是现代操作系统非常喜欢用的一种结构。

### 📝 这一关的期末考点预测（自我检测）

**【选择题预测】**
1. 磁带（或者需要大量连续读取的场景）最适合使用哪种文件逻辑结构？（答：顺序文件）
2. 既要求能够快速随机查找，又要求方便插入和删除记录，应该采用哪种文件逻辑结构？（答：索引文件）
3. 哪种文件结构能够有效地减少索引表所占用的存储空间，同时保持较高的查找效率？（答：索引顺序文件）
4. 文件保护中最常用的，规定了各个用户对文件访问权限的机制叫什么？（答：访问控制表/ACL）

**【判断/简答题眼】**
*   **陷阱：** 文件的逻辑结构和物理结构是一回事吗？
*   *(绝对不是！逻辑结构是用户看到的组织形式如顺序、索引；物理结构是文件存在硬盘里的真实样子，比如连续分配、链式分配。)*
